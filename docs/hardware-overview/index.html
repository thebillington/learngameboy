Hardware Overview

< Hardware

The Game Boy is considered to be quite an underpowered device considering its year of release. This is because Nintendo wanted to keep the device as cheap as possible as well as ensure that the portable handheld had an excellent battery life. This isn't to say that the simple hardware made the device easy to write code for - in fact the simplicity meant that game designers had to come up with creative ways to create great games for the console.

Below is a brief overview of the CPU, Memory Map, Screen and RAM. Once you have read through everything on this page, check out the menu at the bottom to go into more depth on each individual section.

The CPU

The Game Boy CPU (Central Processing Unit) performs all of the mathematical and logical functions required in your game, as well as being in charge of moving memory from one location to another. It is not too dissimilar from any other CPU at a basic level, however there are a number of unique features that weren't used on many other mainstream CPUs of the time, particularly the use of memory mapped I/O (Input and Output).

The Game Boy CPU (Sharp LR35902) was developed by Sharp and is the lovechild of 2 other popular CPUs of the time, namely the Zilog Z80 (used most famously in the ZX Spectrum) and the Intel 8080, an incredibly popular CPU used in many home computers throughout the late 70s to early 80s. The LR35902 included many features from both the Z80 and 8080 as well as including its own instructions for interacting with memory and custom routines to help with sound generation.

You don't have to be an expert mathematician in order to write code, but there is a very important mathematical concept that you will need to understand in order to access the next section of the tutorials. If you don't already know what the binary and hexadecimal number systems are, or how to convert from hex to binary and vice versa then make sure you check out the introductory maths tutorials for everything you need to know.

Memory map

The Game Boy has a relatively unique way of interacting with I/O devices in so far as it does not send data through a single register as is common on many other CPUs, but instead has all of its available devices mapped directly. If you aren't familiar with the way that other CPUs operate then at this stage I wouldn't worry too much about the difference - we will show you everything you need to know to understand how the Game Boy memory map works. But bear in mind that if you ever look at writing code for other CPUs you may find there are large differences with the way you interact with I/O devices such as the screen or hardware buttons.

The Game Boy has a memory map that runs from hexadecimal 0000-FFFF. The value FFFF in hex is equivalent to 65,535 in decimal. This means that the Game boy memory map has 65,536 memory locations capable of holding 8 bits each, meaning there are 65,535 locations that can hold a number between 0 and 255.

The memory map is split up into multiple sections each with its own unique job, from holding the game code, to holding the game variables or managing I/O devices. The memory map looks like this:

Start End Use
0000 3FFF 16KB ROM Bank 0
4000 7FFF 16KB Switchable ROM Bank
8000 9FFF 8KB Video RAM (VRAM)
A000 BFFF 8KB External RAM (Cartridge RAM)
C000 CFFF 4KB Work RAM (Main RAM)
D000 DFFF 4KB Work RAM (Switchable RAM in CGB mode)
E000 FDFF 8KB Mirror RAM (unused)
FE00 FE9F Sprite Attribute Table (OAM)
FEA0 FEFF Hardware Reserved (not usable)
FF00 FF7F I/O Registers
FF80 FFFE High RAM (HRAM)
FFFF FFFF Interrupts Enable Register (IE)

Don't worry too much about the memory map now as we will learn more about it as we get started writing code. The main thing to understand is that the CPU can read from or write to any of the memory locations listed above which allows us to control different functions of the Game Boy, from displaying data on the screen, keeping track of important values such as player position or reading the state of the buttons to check if the A button has been pressed.

The screen

The screen of the Game Boy is known as a DMG (Dot Matrix Graphics) display. This means that all graphics displayed on the device are made up of individual 'dots' or pixels. For anyone familiar with modern day displays you may be asking why this would be an issue as all displays are made up of pixels. The difficulty lies in the resolution of the screen - the display of the Game Boy is capable of displaying 160 pixels across by 144 pixels down (160144) which gives us a total resolution of 23,040 pixels. This may seem like a lot, but when you take into consideration that a 1080p HD screen has 1920 pixels across by 1080 pixels down (19201080) giving us a total resolution of 2,073,600 pixels, 100 times more than that of the Game Boy screen.

The screen also has a bit depth of 2 which means each pixel on the screen can only be one of 4 colours:

  • 11 - White
  • 01 - Light Grey
  • 10 - Dark Grey
  • 00 - Black

RAM

RAM (Random Access Memory) is a section of memory made available to store all of the game variables and values, similar to the information that would be stored in traditional games (e.g. is the player jumping, player position, current fall speed). There are three distinct sections of RAM:

External RAM

The first is the external RAM held between addresses A000-BFFF. This is an 8KB RAM that is held on the game cartridge itself - since the inclusion of RAM on a cartridge increases the cost to distribute games, many cartridges such as Tetris chose not to make use of this external RAM chip.

Work RAM (WRAM)

Work RAM is held between addresses C000-DFFF making for a total of 8KB. However on the CBG (Game Boy Color) there were a number of improvements made to the Game Boy hardware, including the addition of a switchable RAM bank from address D000-DFFF. Since we are going to be developing predominantly for the DMG (Original Game Boy) we won't be making use of these switchable ROM banks in these tutorials and will consider the entire Work RAM as a standalone 8KB of RAM.

High RAM (HRAM)

High RAM is a very small bank of RAM locations held from address FF80-FFFE, making it just 127 bytes in size. HRAM has a number of unique properties that set it aside from the Work RAM. Mainly when using HRAM we use it to store the code for the DMA (Direct Memory Access) routine. The DMA is used to copy the Sprite attributes from the specified RAM location into the OAM (Object Attribute Map). Whilst this transfer occurs the WRAM isn't accessible, therefore the code has to be copied directly into HRAM.

Another use of HRAM is for incredibly fast memory access, as there is a specific instruction, LDH (Load from High RAM) which can be used to load data from the HRAM in one less CPU cycle than the standard LD instruction. This is useful for when we are manipulating the same piece of information many times as it reduces the overall amount of time the CPU spends locked on a single calculation.
